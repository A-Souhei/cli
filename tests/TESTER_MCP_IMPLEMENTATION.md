### ✅ 2. Implement "plan_mode" tool

**Status:** COMPLETE

The `plan_mode` tool provides intelligent planning and execution workflow:

**Features:**
- Detects if user input is about writing/updating code in working directory
- Generates a plan with steps using LLM
- Different from `/code mode` (which splits prompts by sentence)
- LLM-based intelligent step generation

**How it works:**
1. **Get all available tools:** Retrieves all MCP tools from PostgreSQL API
2. **Establish the best plan:** Uses LLM to create step-by-step TODO list
3. **Tool matching:** Matches each step with best available tool using semantic search
4. **Return execution plan:** Returns structured plan with tool assignments

**Input Parameters:**
- `prompt`: User's request
- `model`: LLM model to use (default: tinyllama)
- `working_dir`: Working directory
- `auto_execute`: Whether to execute automatically
- `session_id`: For maintaining context

**Output:**
```json
{
  "status": "success",
  "execution_plan": [
    {
      "step_number": 1,
      "description": "Create Python file...",
      "tool": "write_python_code",
      "mcp_name": "coder",
      "similarity": 0.85,
      "status": "pending"
    }
  ]
}
```

## How It Differs from /code Mode

| Feature | /code mode | plan_mode |
|---------|-----------|-----------|
| **Prompt Analysis** | Splits by sentences | LLM-generated plan |
| **Tool Matching** | Semantic search per sentence | Semantic search per step |
| **Planning** | Automatic from split | Explicit LLM planning |
| **Context** | Accumulated in session | Accumulated in session |
| **Execution** | Automatic iteration | Plan-based iteration |
| **Keywords** | `/code` prefix | `plan`, `test`, etc. |

```python
    module_to_test="module",
    test_functions=["test_func1", "test_func2"]
)

# Run tests
run_pytest(
    test_path="tests/test_module.py",
    verbose=True
)

# Validate
validate_with_test(
    code_file="module.py"
)
```
