1. RETRIEVE_ALL_TOOLS IMPLEMENTATION
   Location: /home/user/cli/system_mcps/coder/server.py (lines 1084-1137)
   
   Purpose: Finds relevant MCP tools using semantic similarity matching
   Input: Array of prompts (e.g., ["Run Python code", "Detect code"])
   Output: Best-matching tool for each prompt with similarity score (0-1)
   
   How it works:
   - Validates prompts array (must be non-empty)
   - Calls PostgreSQL API: POST /mcp-tools/retrieve
   - API generates embeddings (384-dimensional vectors)
   - Performs cosine similarity matching
   - Returns results with similarity scores

2. ROLL_THE_DICE IMPLEMENTATION
   Location: /home/user/cli/system_mcps/coder/server.py (lines 1139-1385)
   
   Purpose: Executes multiple tools iteratively within a session
   Key Requirement: MANDATORY session_id for context persistence
   
   Steps:
   1. Validate session_id (fails if missing!)
   2. Retrieve tools via retrieve_all_tools endpoint
   3. Extract and deduplicate tools
   4. ITERATE through each tool (mandatory execution)
   5. Infer parameters based on tool type
   6. Call tool recursively
   7. Aggregate results

3. DATABASE ARCHITECTURE
   PostgreSQL Table: mcp_tools
   - id: Primary key
   - mcp_name: "coder", "analyzer", etc.
   - tool_name: "run_python_code", "detect_code", etc.
   - description: Full tool description (used for embedding)
   - embedding: 384-dimensional JSON vector (all-MiniLM-L6-v2)
   - created_at, updated_at: Timestamps

4. API ENDPOINTS (Port 15000)
   
   POST /mcp-tools/store
   - Store tool with embedding
   - Auto-generates embedding from description
   
   GET /mcp-tools
   - List all stored tools
   
   POST /mcp-tools/match
   - Single prompt matching (returns best match)
   
   POST /mcp-tools/retrieve
   - Multi-prompt recursive retrieval (returns best match per prompt)
   - This is the key endpoint used by retrieve_all_tools

5. TRANSFORMER SERVICE (Port 16050)
   Model: all-MiniLM-L6-v2 (Sentence Transformers)
   Dimensions: 384
   Size: ~80MB
   
   Endpoints:
   - GET /embed?text=<text> - Single embedding
   - GET /embed/batch?texts=<json> - Batch embeddings
   - GET /similarity?text1=<>&text2=<> - Compare vectors

7. SIMILARITY MATCHING ALGORITHM
   
   Cosine Similarity (lines 325-337 in postgresql/app.py):
   
   similarity = dot_product / (magnitude1 * magnitude2)
   
   Range: 0.0 (completely different) to 1.0 (identical)
   Default Threshold: 0.5
   
   Process:
   1. Embed both texts to 384-dimensional vectors
   2. Calculate cosine angle between vectors
   3. Score >= threshold = match
   4. Sort by similarity (highest first)

9. CRITICAL IMPLEMENTATION DETAILS
   
   - retrieve_all_tools returns ONE best_match per prompt, not all matches
   - roll_the_dice REQUIRES session_id (no default)
   - max_tools in roll_the_dice is capped at 1-10 (default 3)
   - Parameters are auto-extracted by PostgreSQL API
   - All tool results are JSON (must parse manually)
   - Embeddings stored as JSON arrays in database
